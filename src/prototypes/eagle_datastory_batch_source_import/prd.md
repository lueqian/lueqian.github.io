# 重点源信源批量导入与建库需求方案 (PRD)

---

## 1. PRD (产品需求文档)

### 1.1 需求背景与核心价值

* **业务痛点：** 现阶段舆情分析师、运营人员通过单条输入关键字或 URL (统一资源定位符/主页链接) 逐一搜索并添加信源，在面对数十到数百个行业竞品、涉事博主清单时，机械重复操作耗时长、漏检率高。
* **业务目标：** 提供基于 Excel 表格文件的单列 URL (主页链接) 批量导入检索通道，结合底层海量账号库进行毫秒级实体匹配，将“匹配成功”、“多实体冲突选择”、“未匹配自动补采”集成在闭环 Modal (模态弹窗) 中，大幅缩短信源池搭建周期。

---

### 1.2 业务全流程

```text
[用户触发] 
  └─ 点击【批量导入检索】(信源搜索首页 / 搜索结果页右侧)
       │
[文件上传与本地预检]
  ├─ 校验文件类型 (.xlsx, .xls, .csv) 与上限 (≤ 500行)
  └─ 剔除纯顶级域名/公共入口 (如 weibo.com, douyin.com)
       │
[后端数据匹配引擎]
  ├─ URL 清洗与参数剥离 (去除 UTM 追踪参数、分享尾缀)
  └─ 数据库批量倒排索引点查
       │
[结果呈现与交互闭环 (Modal 内)]
  ├─ 标签页 1：精准匹配 (1:1) ── 默认全选，支持按需勾选
  ├─ 标签页 2：冲突实体 (1:N) ── 单选卡片左右并排展示，用户手动指定唯一账号
  └─ 标签页 3：未命中链接 ──── 提供【一键复制】与【批量提交后台自动采集】
       │
[目录绑定与提交]
  ├─ Modal 底部直接选择【现有重点源目录】或【新建目录】
  └─ 点击【确认导入目录】
       ├─ 已匹配账号：实时写入目标目录，完成入库
       └─ 勾选补采链接：推入 Crawler (网络爬虫/数据采集器) 异步队列并记录目录元数据
            └─ 采集完成入库后，用户【下次登录系统】时弹出通知
```

---

### 1.3 功能详细设计

#### 1.3.1 功能入口

* **信源搜索初始页：** 在主搜索框与右侧蓝色【搜索】按钮之间，或紧邻搜索按钮右侧，增设幽灵线框按钮：`【批量导入检索】`。
* **搜索结果展示页：** 在顶部次级搜索框右侧同步保持该按钮常驻，保持搜索上下文连贯。

#### 1.3.2 导入模态弹窗 (Modal) 交互流转

##### 第一阶段：文件上传

* **支持格式：** `.xlsx`、`.xls`、`.csv`。
* **容量限制：** 单次导入限制 **1 ~ 500 条** 链接（超过 500 条直接 Toast (轻提示) 阻断报错：“单次上传不可超过 500 条链接”）。
* **模板下载：** 提供简易模板下载链接（仅包含一列必填项：`用户主页链接`）。
* **拖拽/点击上传：** 支持拖拽解析，解析过程中显示带有动效的 Progress Bar (进度条)。

##### 第二阶段：预校验与通用域名拦截

* **过滤规则：** 正则匹配仅保留具备平台唯一路径特征的 URL (主页链接)。
* **黑名单拦截：** 若检测到各主流社交平台的公共域名且无具体路径（例如：`https://weibo.com`、`https://www.douyin.com`、`https://www.xiaohongshu.com`），直接识别为“无效通用链接”，不进入库表检索，在结果中标记为“无效 URL (主页链接)”。

##### 第三阶段：匹配结果与分流处理

解析完成后，弹窗主体展示三类结果 Tab (标签页)：

| 结果类别 | 命中逻辑 | 界面交互与操作说明 |
| --- | --- | --- |
| **精准匹配 (1对1)** | 单个 URL 唯一匹配到库中 1 个有效用户 | • 列表展示：头像、昵称、所属站点、UID (用户唯一标识)、粉丝数、认证类型。<br/>• 默认全部勾选，支持单独取消勾选。 |
| **实体冲突 (1对多)** | 单个 URL 匹配到历史采集或多版本快照中的 2 个及以上实体 | • 每个 URL 作为一个独立行，左右并排展示候选实体卡片。<br/>• 强制采用 **Radio Button (单选框)**：用户必须单选 1 个目标账号，或选择“放弃添加此链接”。 |
| **未命中链接** | 数据库中未查询到发帖或账号记录 | • 提供只读文本框与 **【一键复制全部未匹配链接】** 按钮，便于排查。<br/>• 提供复选框：`[√] 提交后台自动采集并在采集完成后自动加入该目录`（默认勾选）。 |

##### 第四阶段：目录绑定与提交

* **目录选择器：** Modal (模态弹窗) 底部左侧嵌入目录挂载控件：
  * 单选 A：`加入现有重点源目录`（下拉搜索选择，显示已有目录名称与当前账号余量）。
  * 单选 B：`新建目录`（输入框限制 20 字符以内，支持选择可见范围：`所有人可见` / `个人可见`）。
* **配额校验：** 提交时实时计算“已选账号数 + 冲突已选数”是否超过当前目录或系统配置的容量上限（Quota Limit），若超限则高亮提示并禁用提交按钮。
* **确认导入：** 点击【确认导入目录】，直接将账号与目标目录进行外键绑定并持久化入库，关闭弹窗并弹出全局成功 Toast (轻提示)。

---

### 1.4 异步采集与下次登录提醒机制

1. **元数据关联：** 用户提交未命中链接采集任务时，后端在采集任务队列中写入元数据 Payload (负载数据)：`{ task_id, url, target_directory_id, created_by_uid, created_at }`。
2. **入库挂载：** 当 Crawler (网络爬虫/数据采集器) 成功解析该账号并完成首条数据索引入库后，后台服务触发异步 Webhook (网络钩子/回调通知)，自动将该账号加入 `target_directory_id`。
3. **下次登录弹窗 (Next-login Modal)：**
   * 后端为该用户的待提醒队列增加一条已完成记录。
   * 用户下一次成功登录系统并进入主控制台时（可通过“场景模拟”触发），触发全屏居中通知弹窗：
   > **信源补采成功提醒**  
   > 您于 `2026-XX-XX` 提交的 `3` 个未匹配信源已成功采集入库，并已自动添加到重点源目录：`【涉华核心监测】`。
