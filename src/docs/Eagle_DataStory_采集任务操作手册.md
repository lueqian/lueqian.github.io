# 蓝鹰-采集任务功能操作手册

## 一、 项目背景

在日常网络舆情监测业务中，常规泛化监测系统往往只能覆盖全网宏观态势，而对于突发事件发酵中的特定热点专题、高危信源账号（重点源）以及核心争议单体网帖/链接，急需具备及时、高频和定向化的数据追踪与深度挖掘能力。

其中，采集任务作为定向追踪的总控调度枢纽，承接来自全网专题、重点源以及主动配置发起的采集需求，提供多平台、多维度、多周期的任务调度与多层级结果穿透回溯，全面保障关键舆情事件追踪的即时性、完整性与资费透明度。

---

## 二、 功能概述

采集任务子页是蓝鹰系统中用于对特定舆情事件、关键信源或指定网帖进行**定向追踪**的总调度台。主要功能如下：

1. **定向追踪两类核心数据（采什么）**：
   * **互动量更新**：定期追踪目标网帖的点赞、收藏、转发、评论等客观数值波动，掌握热度走势；
   * **评论区采集**：深入抓取主帖下方的网民直接评论内容、发评人昵称与发评时间，直观研判受众态度与社情民意（不采集二级评中评）。
2. **覆盖三类采集对象（采谁的内容）**：
   * **全网专题**：直接绑定已有专题，自动追踪该专题名下收录的关联帖文；
   * **重点源**：直接绑定核心信源账号，持续监控该账号发布的最新帖文动态；
   * **自定义链接**：支持单帖分析，或通过批量粘贴、CSV 模板批量导入特定网帖链接。
3. **灵活的规则化频次设置（何时采、采多久）**：
   * 用户可根据舆情发展的不同阶段，添加一条或多条规则。例如在事件高发期设置“每隔 2 小时采集一次”，平稳期调整为“每天固定 16:00 采集一次”，兼顾高频追踪与资源利用率。
4. **稳妥的状态与权限控制（为什么限制修改）**：
   * **保障任务稳定性**：如果任务正在执行时允许随意更改任务类型或大幅调整参数，极易打乱后台调度，甚至导致正在采集的数据缺失或统计口径混乱；
   * **按采集目标划分的精细修改权限**：
     * **若采集目标为全网专题或重点源**：已绑定的专题和重点源目录**不允许修改**（如需监控其他目录请新建任务），但允许调整后续频次或停用任务；
     * **若采集目标为指定链接**：允许在链接明细列表中**随时新增、删除要采集的链接**，以及调整后续频次或停用任务；
     * **核心属性锁定**：无论哪类任务，均**不允许变更任务类型**（如互动量更新与评论区采集之间禁止互相切换）；
   * **仅未来批次生效**：修改频次等设置后，**调整仅对后续未生效、未下达的新批次生效**，绝不干扰当前正在抓取或已完成的历史采集批次，以此减少动态调整带来的不确定性。
5. **透明的额度预估与成果穿透（看消耗与查成果）**：
   * 创建前系统会自动预估每日消耗额度，若选中的专题/信源无内容会主动阻断提示，避免无效消耗；
   * 采集完成后按执行批次清晰呈现流水记录，评论数据支持按网帖卡片聚合展示，方便逐帖展开查验。

## 三、 按模块输出操作步骤

### 模块一：采集任务检索与综合筛选

用于在海量定向任务中快速定位目标任务，把控系统运行态势。

#### 1. 操作步骤

| 步骤序号 | 操作要点 | 界面位置与交互说明 |
| :--- | :--- | :--- |
| **步骤 1** | **关键字模糊搜索** | 位于列表上方左侧「搜索任务名称」输入框，支持输入任务名称的部分关键词。 |
| **步骤 2** | **多维属性组合过滤** | 依次使用筛选下拉框：<br/>• **任务类型**：单选「互动量更新」或「评论区采集」；<br/>• **范围**：单选「专题」、「重点源」或「链接」；<br/>• **采集来源**：支持多选（如同时勾选小红书、抖音、微博等）；<br/>• **任务状态**：单选「未开始」、「进行中」或「已结束」。 |
| **步骤 3** | **重置与排序** | 点击筛选区末尾的「重置」按钮可一键清空全部筛选条件；点击表头「最近更新」列可进行升序/降序排列。 |

#### 2. 预期输出与数据判读标准

* **正常情况**：
  * 输入关键词或选择过滤条件后，列表即时响应过滤，只展示完全符合交集条件的任务记录；
  * 表格各字段（任务名称、类型标签、范围胶囊、来源平台图标、频次、追踪天数、状态、最近更新时间）完整显示；
  * 点击「重置」后，条件清空并恢复默认全量列表。
* **异常情况**：
  * 若筛选条件组合后列表显示为空，需检查是否存在冲突条件（如选择“互动量更新”且状态为“未开始”，但实际当前无该组合任务）；如确认有任务但未查出，需排查是否关键词含有不可见特殊字符。

### 模块二：新建定向采集任务

支持在管理页直接新建，或通过外部模块（全网专题、重点源、全网搜索）带参快捷唤起。

#### 1. 操作步骤

##### 步骤 1：打开新建抽屉
在任务列表右上角点击蓝色**「新建任务」**按钮，系统从屏幕右侧滑出配置抽屉，标题展示为“新建采集任务”。

##### 步骤 2：配置任务基本要求
1. **输入任务名称**：文本框录入任务标识（最大限制 50 字符，右下角带有计数器），如 `某专题定向采集监控`。
2. **选择任务类型**：
   * 单选「**互动量更新**」：侧重监测点赞、转发、收藏、评论总量等宏观数值走势；
   * 单选「**评论区采集**」：侧重抓取网民客观发评言论，用于分析受众情绪与社情民意。
3. **设置更新频率与采集周期**：
   * 系统支持按需添加一条或多条**采集规则**，每条规则均包含“时间范围”与“采集频次”两个核心条件：
     * **频次项 A（每隔 N 小时）**：设置生效时间范围（开始日期至结束日期），并指定每 `1~24` 小时（默认每 2 小时）采集一次；
     * **频次项 B（每天固定 N 点）**：设置生效时间范围，并指定每天固定时间点（如 `08:00`、`16:00`）采集一次；
   * **多规则组合（满足个性化需求）**：点击「添加自定义规则」，可为不同时间段规划差异化频次（例如：事件发酵前3天按每2小时高频抓取，进入稳定期后4天调整为每天固定16:00抓取一次）。系统整体任务时间范围将自动取所有规则时间段的包络并集。

##### 步骤 3：配置任务对象与采集范围（三选一联动）
* **场景 A：选择全网专题（topic）**
  1. 下拉框选择目标专题（如“某专题一”）；
  2. 系统联动检测网帖量：匹配到数据时在右下方显示篇数提示；若为 0 篇则提示红色内联警示；
  3. 设定追踪天数（`T+0 ~ T+7`）；
  4. 勾选采集来源平台；若为评论采集，可分平台设置深度（前 1/3/5/10 页）。
* **场景 B：选择重点源（source）**
  1. 下拉框选择目标重点源目录（如“某重点源一”）；
  2. 设定追踪天数、来源平台及采集深度。
* **场景 C：选择链接（other）**
  1. 可以在多行文本框中直接批量粘贴网帖 URL，也可以点击**「文件模板下载」**获取 CSV 模板，编辑后点击**「导入文件」**批量载入；
  2. 点击**「解析并导入」**，下方表格将自动识别域名对应的平台（如哔哩哔哩、抖音、小红书等）及格式有效性；
  3. 支持在表格中行内点击「修改」修正链接或点击「删除」移除不需要的链接；
  4. 对识别出的各个平台独立配置评论区采集页数。
* **额度预估看板**：
  配置完成后，抽屉底部自动触发防抖计算并展示看板：明确告知预估每日消耗额度；若有平台勾选了“前10页”，将展示橙色风险警示。

##### 步骤 4：前置校验与提交保存
1. 点击抽屉底部蓝色**「提交」**按钮。
2. **零数据阻断确认**：若关联专题/重点源有效网帖为 0，系统弹出阻断二次确认弹窗：`当前选择的关联目录暂无舆情数据，系统将无法立即执行采集，是否仍按照现有配置创建？`，需用户二次确认。
3. 提交成功后提示：`任务创建成功，请在列表中手动开启`，新记录默认以「未开始」状态插入列表首行。

#### 2. 预期输出与数据判读标准

* **正常情况**：
  * **导入链接解析结果**：明细表格中每条链接被精准归类至对应平台（如微博、小红书等），状态显示绿色“有效”；
  * **额度预估结果**：展示具体的“预计消耗额度：X 次/天”，数值依据【链接数 × 频次轮数 × 页数系数】正确核算；
  * **提交后列表呈现**：任务列表第一行新增一条任务记录，初始状态为“未开始”，累计采集量与增量显示为 0，最近更新时间显示为 `-`，等待用户手动启动。
* **异常情况**：
  * **链接无效**：若链接表格中状态显示为红色“无效”，说明 URL 格式不符合支持平台的官方规则，提交时系统会校验拦截并提示“请在下方表格中录入或修改至少一条有效链接”；
  * **零匹配对象创建**：若用户未仔细核对直接强行提交 0 篇网帖的专题/重点源任务，任务即使启动也不会产生采集流水，属于无效任务配置。

### 模块三：任务生命周期状态控制与日常维护

#### 1. 操作步骤

1. **任务启动（未开始 → 进行中）**：
   * 新建任务初始状态为「未开始」且初始数值置 0。在列表中找到该任务并点击启动，状态流转为蓝色的「进行中」，任务即刻被系统调度拉入执行队列，后台开始周期性轮询采集。
2. **任务手动结束（进行中 → 已结束）**：
   * 在操作列点击橙色的**「结束」**按钮，系统弹出阻断弹窗：`确认结束任务？结束任务后将不允许手动重启。如需继续采集，需要新建任务。是否确认结束该采集任务？`；
   * 确认后任务变为灰色的「已结束」，系统停止定时调度，且该行的「结束」按钮置灰禁用，防止误重启破坏时序数据一致性。
3. **任务配置修改（基于目标的精细化维护）**：
   * 点击操作列的**「修改」**按钮滑出配置抽屉；
   * **基于采集目标的权限控制**：
     * **全网专题 / 重点源任务**：绑定的专题或重点源目录置灰只读、**禁止修改**；用户可调整后续生效的采集频次规则，或停用任务；
     * **指定链接任务**：支持在链接列表中随时**追加新增链接、删除不需要的链接**，以及调整后续采集频次或停用任务；
     * **核心类型保护**：所有任务的“任务类型”均置灰锁定，严禁在互动量更新与评论区采集之间跨类型变更；
   * **未来生效原则**：频次调整保存后，**仅作用于后续未下达的未来采集批次**，当前正在抓取或已完成的历史批次不受任何影响。
4. **任务删除**：
   * 点击操作列红色的**「删除」**按钮，系统弹出气泡提示：`如需停止采集，建议结束任务，已采集到的数据在任务删除后将无法查看，请知悉。`，点击确认后彻底删除。

#### 2. 预期输出与数据判读标准

* **正常情况**：
  * 启动后状态即刻显示为蓝底「进行中」，最近更新时间随批次执行更新为对应的时间戳，累计量与增量开始产生数值变化；
  * 点击“结束”确认后，状态即刻变为浅灰底「已结束」，该任务不再下发新的采集批次；
  * 删除后任务行即刻从当前视图移除，总条目数减 1。
* **异常情况**：
  * 若任务启动后超过预定采集时点 30 分钟以上，状态虽为“进行中”但累计数据始终为 0 且最近更新时间未刷新，需检查账户余额是否欠费阻断，或该任务范围内的所有目标链接是否均已被平台封禁。

### 模块四：采集成果多层级穿透与深度研判（任务详情）

在列表点击任意行的**「详情」**操作，页面由列表视图切换为单任务深度详情视图。

#### 1. 操作步骤

##### 结构总览
```text
任务详情页结构:
├── [顶部导航条] 返回列表按钮 + 页面主标题
├── [模块一: 任务概况]
│   └── 任务名称 / 类型 / 范围 / 平台 / 频次 / 追踪天数 / 状态 / 最近更新时间 / 创建时间
└── [模块二: 采集详情]
    └── 批次列表 Table: 采集批次 | 执行时间 | 采集状态 | 抓取有效链接数 | 本次消耗额度 | 操作(详情)
        └── [点击详情] -> 滑出 850px 宽度的「采集批次详情抽屉」
```

##### 批次详情抽屉查看：
1. **互动量更新任务**：
   * 查看表格列出的受监测网帖列表，涵盖网帖标题、平台信源 Tag、作者、最新抓取互动量快照（格式：`赞 X / 藏 Y / 转 Z / 评 W`）；
   * 点击`查看网帖 →`可直接外链跳转至社交媒体原帖核验真实性。
2. **评论区采集任务（双重视图切换）**：
   * **按网帖聚合视图（默认推荐）**：主表格以受监测的网帖为主体，展示网帖标题（两行截断带外链跳转）、平台彩色信源 Tag、原帖作者、抓取评论数 Badge 以及最新发评时间。点击右上角「全部展开/全部收起」或单行展开按钮，展开浅灰色子表格，查看该帖下的抓取评论明细；
   * **按评论平铺视图**：切换至该模式，所有抓取到的评论按单行平铺罗列。

#### 2. 预期输出与数据判读标准（正常 vs 异常情况判读）

* **理论上正常情况应包含的数据**：
  * **批次列表**：每次定时下达均应产生一条对应时点的批次记录（如“第 3 次采集”），包含正确的执行时间、采集状态（全部成功）、本次有效链接数及扣除的额度次数；
  * **互动量数据**：每条链接应返回完整的四维互动数值（点赞数、收藏数、转发数、评论数）；
  * **评论区数据**：应按照链接（主帖）归集并完整展示采集到的评论明细，必须包含**评论内容文本、发帖人（评论者）昵称、发评时间**三项核心数据。
* **数据为空时的正常与异常界定**：
  * **【属于正常情况的空数据】**：
    * **新发网帖无互动/无评论**：当任务内包含的部分链接本身热度较低，或者属于发布时间较短的冷门网帖，确实没有任何网民在其下方发表评论。此时批次状态显示“采集成功”，但该网帖下“抓取评论数为 0”或“未采集到有效评论”，**这属于完全正常的业务现象**；
    * **互动数值无增长**：连续两个批次抓取到的点赞或评论数一致，增量为 0，说明该时间段内无新互动产生，亦属正常。
  * **【必须警惕的异常情况】**：
    * **已知有评论但结果全为空**：人工在浏览器中打开原帖确认存在大量热评，但系统采集抽屉内该帖的评论列表始终为空；
    * **大面积持续性返回为空**：当一个任务下达采集后，每个批次或绝大部分批次返回的内容均大面积全为空，且各平台链接均无法回显有效数据。
    * **处置指引**：出现此类大面积持续为空情况，通常由于目标平台升级反爬风控规则、请求被拦截、或源链接失效导致，**请第一时间联系系统负责人或技术支持协助排查定位问题**。

## 四、 功能使用注意事项

> [!IMPORTANT]
> **1. 单任务单批次 50,000 条链接限制与时效预期**
> * **链接上限控制**：系统限制**单一任务单批次采集的单个平台有效链接不能超过 50,000 条**。该限定是为了保障任务下达后能在一个合理的预期时长内产出结果；
> * **返回时效预期**：对于包含数千至数万级链接的大型采集任务，在平台资源无异常的情况下，用户通常在 **1～2 小时内**能够陆续获取到完整的采集结果。实测表明，若单平台单批次链接超过 50,000 条，会导致平台反爬风险骤增、任务失败率显著上升且返回速度大幅减慢；
> * **建议**：如确有极大规模链接需要监测，建议拆分为多个子任务分批执行。

> [!WARNING]
> **2. 评论区采集边界与平台采集成功率差异**
> * **仅采集一级主评论（不采集评中评）**：评论区采集能力仅对主帖下方的一级评论进行抓取与分析，**不会采集二级楼中楼回复（评中评）**。在研判评论总数与系统显示数据时请以此为准；
> * **成功率与平台风控特性**：根据当前各平台的反爬成本与采集资源配置，各社交媒体平台的采集难度存在客观差异：
>   * **微博、小红书**：平台反爬策略较严、风控对抗激烈，一般情况下**采集失败率相对较高**（可能出现部分链接无法抓取或字段截断）；
>   * **抖音、今日头条、B站等其余平台**：采集链路相对稳定，**采集成功率较高**。

> [!NOTE]
> **3. 任务分批调度与数据回收时效机制**
> * **调度下达时效**：系统会根据设定的频次准时下达任务。例如任务设定为周期内每天 16:00 进行一次采集，系统就会在每日 16:00 整点统一生成该批次任务并下发范围内所有链接；
> * **数据回收节奏**：采集结果的返回速度与当前全公司在跑的总任务并发数、以及单次采集任务的体量直接相关。系统后台会对任务进行分批排队并发采集，**保守测试一般在采集任务下达后的 30 分钟内会陆续回收并展示数据**。用户无需重复刷新，静待数据流式回填即可。

> [!CAUTION]
> **4. 计费前置校验与“调用即计费”原则**
> * **余额前置校验**：启动或创建任务前，系统会校验账户数据包额度。若账户余额不足（额度 $\le 0$），将无法开启任务，系统将提示“额度不足，请联系管理员充值”；若登录时账户低于预警阈值（默认 20%），会触发全局强提醒；
> * **调用即计费（不论成败）**：社交媒体平台存在不可控的风控拦截或作者删帖等情况。每次采集任务执行时，**无论目标平台最终返回有效数据还是因客观风控导致结果为空，只要系统向平台发起了有效调用，均会产生并扣除对应的额度**；异常记录在额度明细中均有专属错误码留痕备查。

> [!WARNING]
> **5. 任务手动结束的不可逆保护**
> * 采集任务处于「进行中」时，一旦通过操作列点击「结束」并二次确认关停，**该任务将永久进入「已结束」归档态，不允许手动再次重启**；
> * **设计初衷**：防止用户在断档数天后重新开启，导致时序波动折线出现严重跳空与统计口径失真。如需继续监控该对象，必须新建任务。

> [!NOTE]
> **6. 任务修改锁定与未来生效原则**
> * **目标与类型保护**：专题和重点源任务禁止修改所属目录，链接任务仅开放链接的追加与删除，所有任务严禁跨类型变更，确保历史采集数据一致性；
> * **未来批次生效**：对采集频次的任何调整，**仅对保存后未下达的未来批次生效**，绝不回溯或中断当前批次。
